# フェーズ 2 の結果 (データ)

実施: 2026-10-03〜04。環境: 開発 PC (ワークショップ `gpu`、GTX 1660 Ti)。
Claude Code の呼び出し (`claude -p`) はワークショップの外のホストで実行した。

## まとめ

- 学習データは Claude Code (Sonnet) のラベルで 3,000 件できた (`data/train-claude.jsonl`、質問 41 問)
- **zero-shot のペア方式 (mDeBERTa) は、この質問セットでは教師に使えない**。ほとんどの質問に「真」と答え、
  Claude と判定が同じになるのは noul で 37% だけだった
- Sonnet と Opus の判定は noul で 95% 一致した。外れているのはペア方式のほう
- 残っているのは、評価セットの人による見直しと、混ぜ方・合格ラインの決定 (下の「残っていること」)

フェーズ 3 で移す。

## 2. 状態

業種、用件、感情、求めること、長さ、文体の条件をスクリプトが乱数で決め、1 回の呼び出しで 25 件ずつ書かせた。
約 3 割には「文面は丁寧だが不満が読み取れる」などの、判断が難しくなる条件を足した。

- 3,000 件すべて違う文。文字数は最短 16、中央値 122、最長 509
- トークン数は中央値 59、最大 238。パック方式の上限 (384) で切れる状態はない
- 分野はほぼ均等 (2,800 件の時点で、配送 535 / 品質 539 / 料金 575 / 操作方法 543 / その他 608)
- 「お世話になっ…」で始まる文が約 1 割ある

`meta` は書かせたときの条件で、正解ラベルではない。

## 3. 2 つの教師の比較

ペア方式は系列長 288 (状態が切れない長さ)、温度 1。Claude Code は Sonnet。

| 比べたもの | 件数 | noul の平均の確率 | noul の判定が同じ割合 | 確率の差の平均 |
|---|---|---|---|---|
| ペア方式 と Sonnet (学習用) | 704 | 0.707 / 0.193 | 0.368 | 0.536 |
| ペア方式 と Opus (評価用) | 300 | 0.718 / 0.209 | 0.366 | 0.537 |
| Sonnet と Opus (評価用) | 300 | 0.188 / 0.209 | 0.952 | 0.050 |

choice の選択が同じ割合:

| 比べたもの | topic | sentiment | intent | urgency | wants |
|---|---|---|---|---|---|
| ペア方式 と Sonnet (学習用) | 0.441 | 0.730 | 0.230 | 0.207 | 0.380 |
| ペア方式 と Opus (評価用) | 0.543 | 0.700 | 0.227 | 0.277 | 0.420 |
| Sonnet と Opus (評価用) | 0.833 | 0.923 | 0.827 | 0.870 | 0.893 |

- ペア方式は「真」に寄る。「本人ではない人が代わりに問い合わせていますか？」の平均が 0.89 (Sonnet は 0.05)、
  「文面に皮肉が含まれていますか？」が 0.90 (同 0.14)。緊急度を「高い」とした割合は 83% (同 13%)
- フェーズ 0 で見た傾向 (真が 50% の評価セットで平均 0.70〜0.75) と同じ。この質問セットは真の割合が低い質問が多いので、
  判定の大半が食い違う
- Sonnet と Opus で差が大きいのは、程度を聞く質問 (`polite` 0.797、`frustrated` 0.853、`complaint` 0.863)
- どれも人の正解との比較ではない。Claude が正しいかどうかは、評価セットを人が見直してから測る

ペア方式のラベル付けは 704 件で止まった (開始から約 15 分で書き込みが止まり、プロセスは残ったまま GPU を使っていなかった。
原因は未確認)。上の結果から学習には使わない見込みなので、回し直していない。
速さは 1 件 (59 ペア) あたり約 1.5 秒。

## 4. Claude Code のラベル

- noul の「真」(確率 0.5 超) の割合は、質問によって 3.6% (`login`) 〜 62% (`polite`)。
  5% 未満の質問が 5 つある (`cancel`、`wrong_item`、`double_charge`、`login`、`proxy`)
- 0.2〜0.8 の中間の確率は、noul のラベルの 14%
- 疑問文と平叙文の言い換えの判定は、99.0〜99.7% 一致した
- 10 件を目で確かめた範囲では、1 件の間違いがあった (前回の問い合わせに返事がないと書いた文で、`repeat` が 0.06)

呼び出しの失敗:

- ラベル付けの 1 回目は 300 回のうち 165 回が失敗した。エラーの中身を記録しておらず、原因は未確認。
  回し直すと通った。いまは失敗時の出力を表示する
- 答えの質問が欠ける (30 件。ほとんどが `personal_info`)、JSON のあとに余分な文字が付く (2 回) という失敗もあった。
  どちらも回し直しで埋まった
- 答えには番号 (`i`) を付けさせ、状態と答えがずれないようにした

## 残っていること

1. **評価セットを人が見直す**: `data/eval-draft.jsonl` は Opus の下書き。300 件 × 41 問は多いので、質問や件数を絞るかを決める
2. **混ぜ方 (未決事項 7)**: ペア方式と平均すると、偏りを学習データに持ち込む。Claude のラベルだけを使う案が有力
3. **フェーズ 3 の合格ライン**: 「ペア方式との差が 1〜2 ポイント以内」は、zero-shot のペア方式が基準では意味がない。
   同じ学習データでファインチューニングしたペア方式を基準にする案が有力
4. **真の割合が低い質問**: 5% 未満の質問は、真の例が 100〜150 件しかない。状態を足すか、質問を見直すかを決める
