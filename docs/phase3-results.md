# フェーズ 3 の結果 (学習と較正)

実施: 2026-10-05。環境: 開発 PC (ワークショップ `gpu`、GTX 1660 Ti)。
学習データは `data/train-claude.jsonl` (3,000 件。うち 1 割の 300 件を検証データに分けた)、
評価は `data/eval-draft.jsonl` (300 件 × 41 問。Opus が付けた下書きで、人の見直しはまだ)。

## まとめ

- パック方式を学習できるようにした (`train --arch packed`)。評価セットの正解率は **noul 0.934、choice 0.838**
  (学習前は 0.341 / 0.410)
- 同じ学習データで学習したペア方式 (noul 0.937、choice 0.833) との差は、noul が −0.3 ポイント、choice が +0.5 ポイント。
  ECE も同じ水準で、**合格ライン (差が 1〜2 ポイント以内、ECE が同等以下) を満たした**
- 「状態も質問を見る」版は良くならなかった (noul 0.933、choice 0.831)。**「状態は質問を見ない」版を採用する**
- 温度は、ラベルを 0 / 1 に丸めてから求める。教師の確率のまま合わせると、ECE がかえって悪くなった
- 注意: 評価セットの正解は Opus のラベルで、質問は学習と同じ 41 問。人の正解での確認と、学習にない質問での確認はしていない

## 1. 作ったもの

| ファイル | 内容 |
|---|---|
| `train.py` | ペア方式とパック方式の学習。どちらも新しい形式 (1 行 = 1 つの状態 + 複数の質問 + labels) を読む |
| `evaluate.py` (新規) | 判断ロジットの収集 (`score`)、温度の較正 (`calibrate`)、指標 (`metrics`) |
| `calibration.py` | choice の温度 (`fit_temperature_choice`) と指標 (`choice_metrics`) を追加 |
| `packed_model.py` | 役割埋め込みの保存と読み込み (`role_embeddings.safetensors`)、`state_sees_questions` |
| `cli.py` | `train` に `--arch` / `--eval-data` など、`evaluate` コマンドを追加 |
| `scripts/phase3/compare.py` | 学習したモデルを比べる表を出す (この文書の 2〜4 節の数字) |

学習のしかた (ペア方式とパック方式で共通):

- 損失は質問ごと。noul はソフトラベルの BCE、choice は教師の分布とのクロスエントロピー
- 1 ステップは状態 8 件。状態ごとに、質問の数 (1〜41)、質問の順番、選択肢の順番を乱数で変える
- 単語埋め込みは凍結、fp32、gradient checkpointing。1 回の順伝播は 2,048 トークンまでにして、勾配を累積する
- 3 エポック (1,014 ステップ)、学習率 3e-5、最初の 1 割でウォームアップ
- 1 行 1 ペアの古い形式 (`data/sample-pairs.jsonl`) はなくした

プランから変えた点:

- **温度はラベルを丸めてから求める** (3 節)
- **ペア方式も同じ学習データで学習した**。未決事項 7 の「同じ学習データでファインチューニングしたペア方式を基準にする」案を採った

## 2. 3 つのモデルの比較

評価セット。温度は検証データで求めたもの。

| モデル | 型 | 温度 | 正解率 | NLL | ECE | ECE (温度 1) | 検証データの正解率 |
|---|---|---|---|---|---|---|---|
| パック方式 | noul | 0.732 | 0.934 | 0.293 | 0.017 | 0.029 | 0.946 |
| パック方式 | choice | 0.594 | 0.838 | 0.947 | 0.026 | 0.127 | 0.811 |
| パック方式 (状態も質問を見る) | noul | 0.717 | 0.933 | 0.292 | 0.016 | 0.031 | 0.945 |
| パック方式 (状態も質問を見る) | choice | 0.609 | 0.831 | 0.937 | 0.030 | 0.123 | 0.809 |
| ペア方式 | noul | 0.693 | 0.937 | 0.297 | 0.016 | 0.030 | 0.949 |
| ペア方式 | choice | 0.552 | 0.833 | 0.965 | 0.032 | 0.128 | 0.813 |

学習前 (zero-shot、温度 1) は、パック方式が noul 0.341 / choice 0.410、ペア方式が 0.380 / 0.433。

- 件数は noul が 10,800、choice が 1,500。正解率の誤差の目安は noul で ±0.5 ポイント、choice で ±2 ポイントほどなので、
  3 つのモデルの差はどれも誤差の範囲。乱数の種は 1 つしか試していない
- NLL は教師の確率に対する値。教師の確率そのものにあいまいさがあるので、0 には近づかない
- フェーズ 2 で測った Sonnet と Opus の一致は noul 0.952、choice 0.83〜0.92。学習データは Sonnet のラベルなので、
  noul はこの上限に近いところまで来ている

判定が同じ割合 (評価セット。noul / choice):

| | パック方式 | 状態も質問を見る | ペア方式 |
|---|---|---|---|
| パック方式 | — | 0.972 / 0.918 | 0.979 / 0.945 |
| 状態も質問を見る | 0.972 / 0.918 | — | 0.974 / 0.915 |

**「状態も質問を見る」版**: 正解率は上がらず、質問同士の独立もなくなる (評価では 1 つのパックに最大 32 個のマーカーを詰めた)。
採用しない。`state_sees_questions` の設定は残してある。

学習にかかった時間は、パック方式が 45 分、ペア方式が 2 時間 7 分 (どちらも検証データと評価セットの推論を含む)。
GPU メモリのピークは約 3.9 GB。推論の速さ (`examples/review.yaml`、GPU) は、パック方式が 21 ms、ペア方式が 149 ms。

## 3. 温度の求め方

はじめは教師の確率 (ソフトラベル) のまま NLL が最小になる温度を求めた。パック方式では noul 1.23 / choice 1.28 になり、
評価セットの ECE は温度 1 のときより悪くなった (noul 0.029 → 0.050、choice 0.127 → 0.195)。
教師は当たっている質問にも 0.8 のような控えめな確率を付けるので、それに合わせると確率が正解率より低く出る。

ラベルを 0 / 1 に丸めてから (noul は 0.5 以上が真、choice は確率が最大の選択肢) 求めると、温度は 1 より小さくなり、
ECE は noul 0.017、choice 0.026 まで下がった。`evaluate.calibrate` はこの求め方にしてある。

学習の損失はソフトラベルのまま。丸めたラベルで学習する場合との比較はしていない。

## 4. 質問ごと

パック方式が弱い質問 (評価セット。真の割合 / 正解率 / 真を当てた割合):

| 質問 | 真の割合 | パック方式 | ペア方式 |
|---|---|---|---|
| `staff` (担当者の対応への不満) | 0.087 | 0.930 / 0.192 | 0.940 / 0.308 |
| `angry` | 0.200 | 0.860 / 0.350 | 0.873 / 0.417 |
| `personal_info` | 0.033 | 0.967 / 0.500 | 0.970 / 0.500 |
| `urgent` | 0.307 | 0.863 / 0.587 | 0.893 / 0.696 |
| `multiple` (用件が 2 つ以上) | 0.280 | 0.793 / 0.571 | 0.797 / 0.548 |
| `repeat` | 0.140 | 0.917 / 0.643 | 0.923 / 0.738 |
| `complaint` | 0.560 | 0.817 / 0.696 | 0.827 / 0.714 |

- 真を見落とす質問は、ペア方式でも同じように弱い。方式の差ではなく、ラベルか学習データの問題に見える。
  `angry`、`frustrated`、`complaint`、`polite` は、フェーズ 2 で Sonnet と Opus の判定が食い違った「程度を聞く質問」でもある
- 真が 5% 未満の質問 (`cancel`、`wrong_item`、`double_charge`、`login`、`proxy`) は、真を当てた割合が 0.81〜1.00 で、
  少なさのわりに学習できている。ただし評価セットの真は 7〜16 件しかない
- choice の正解率は `topic` 0.870、`sentiment` 0.870、`intent` 0.777、`urgency` 0.843、`wants` 0.830
- 全質問の表は `scripts/phase3/compare.py` で出せる

## 残っていること

1. **評価セットを人が見直す** (フェーズ 2 から持ち越し)。上の正解率はどれも「Opus と同じ判定になる割合」
2. **学習にない質問での確認**: 評価セットの質問は学習と同じ 41 問。質問の文を変えたときや、別の分野の質問でどうなるかは測っていない。
   `examples/review.yaml` (本の感想) では、日本語の noul「書き手はこの本を他人に勧めている」が 0.02 になった
3. **弱い質問** (4 節): `staff` と `angry` は真の半分以上を見落とす。ラベルを見直すか、真の例を足すか
4. 乱数の種を変えた学習、エポック数や学習率の調整はしていない
5. モデル (`models/packed`、1.1 GB) は Git に入れていない。フェーズ 4 でこれを OpenVINO IR にする
